# 软路由体检开发优先级

体检的目标是告诉用户哪一层出问题、凭什么这么判断，以及接下来做什么。公网探测以少量固定目标作为样本。界面展示通过、需核对和未验证的实际数量，方便用户理解某次扫描覆盖了什么。

| 优先级 | 场景 | 值得开发的能力 | 如何验收 |
| --- | --- | --- | --- |
| 已进入预览 | 能 Ping、网页打不开；只有 IPv6 网站异常 | 区分 DNS、IPv4/IPv6 HTTPS 和 Ping，合并为一个可定位的问题，保留证据详情 | 模拟 DNS 故障及仅 IPv6 HTTPS 超时，结果分开呈现；IPv4-only 不报 IPv6 故障 |
| 已进入预览 | 路由器有 IPv6，下面的设备仍无法使用 | 分开检查 WAN 委派和 LAN 前缀分配，对已识别的中继场景跳过路由模式判断 | 模拟有上游前缀、LAN 无分配，能定位到 LAN，同时标明终端待验证 |
| 下一步 | 路由器能上网，某台电脑不能 | 增加终端侧检查，对照客户端网关、DNS、IPv4/IPv6 与路由器报告；先做 Windows 端只读检查 | 仅改一台测试电脑的网关或 DNS，能在报告中指出这台电脑的差异 |
| 接下来 | 装插件后断网；多个 DNS 服务相互影响 | 加入按插件和版本匹配的适配器，识别 DNS 监听、转发链及实际分流；优先验证 NaiLink、AdZero 与本地 DNS 共存 | 在指定固件和插件版本上复现端口占用、服务未启动、转发配置不匹配三种情况 |
| 已进入预览 | 偶尔掉线，打开面板时已经正常 | 本地采样 WAN 网口、PPPoE、双栈默认路由、DNS 和 HTTPS；在首页回放异常及恢复，支持脱敏导出 | 模拟短暂掉线和样本失败，检查事件、恢复时长和内存记录上限 |
| 已进入预览 | 千兆端口降到百兆 | 在拓扑显示可观察端口的当前协商速率、历史基线和掉链次数，持续降速进入回放 | 从模拟的 1000 Mbps 降至 100 Mbps 后告警，回升后记录恢复 |
| 已进入预览 | 上传文件时会议或游戏卡顿 | 并行观察出口流量和固定目标延迟，按相同出口与目标保存轻载参考 | 比对轻载、上传伴随延迟升高、丢包和测试期间出口变化 |
| 已进入预览 | 只有某个网站打不开 | 按输入的域名分别判断 A/AAAA、TCP 443、TLS 和 HTTPS 响应 | 用双栈、仅 A 记录和失败样本验证各阶段显示 |
| 后续 | 不确定该不该清理空间或调整设置 | 先给出本地资源、日志或配置的可核对建议，再扩展确认式修复和变更回退 | 每个修复能复现故障、说明影响、复查结果，并在必要时验证回退 |

现有服务恢复用检查过的动作执行，并在启动后实际查询。涉及防火墙、接口、DNS 策略及文件清理的动作，需要各自的适用条件、确认与复测试例。
